CLI **0.4.0** uses a SQLite domain store and explicit Workspace or Project scope. Provider credentials are separate from public settings. A source checkout and project `.env` file are not required to run the installed CLI.

## Provider credentials

Use [OpenRouter](https://openrouter.ai/keys) for image, video, and LLM requests, and [ElevenLabs](https://elevenlabs.io/app/settings/api-keys) for voice and music. fal, Firecrawl, and Apify are optional connectors. Configure the providers your workflow needs.

For an ordinary Workspace or Project, the resolver tries the encrypted credential for that exact scope, credentials inherited before the CLI starts, a supported provider subscription, then reports missing. Credentials never cross Workspace or Project boundaries. Account-bound credentials use their own account scope.

```bash
ralphy --root <data_root> --workspace <workspace_id> provider auth status openrouter
ralphy --root <data_root> --project <project_id> provider auth status openrouter
```

Use `provider auth set <provider> --stdin` in the same scope to persist a key. Enter it privately in your own terminal, using a hidden prompt or existing shell variable. Never place literal keys in argv, chat, or shell history. Encrypted persistence uses macOS Keychain; on other platforms use credentials exported in the parent shell.

## Environment variables

Export a built-in credential such as `OPENROUTER_API_KEY`, `ELEVENLABS_API_KEY`, `FAL_KEY`, `FIRECRAWL_API_KEY`, or `APIFY_TOKEN` before launching the CLI or the agent that runs it. The process captures only its fixed built-in credential allowlist at startup and removes those names from its live environment. Custom connectors do not add arbitrary environment variable names to that allowlist; configure their credentials with scoped `provider auth set <provider> --stdin`. A project's `.env` is not a provider credential source. `setup --keys-from-env` and key values in setup arguments are refused.

A shell tool such as direnv can supply the parent environment before launch, but Ralphy does not turn a project file into an authorized credential source. Keep private values outside tracked source and generation artifacts.

## Data roots and scopes

Initialize storage without a checkout:

```bash
ralphy --root /absolute/path/to/library setup --non-interactive
```

The returned `data_root` is the directory containing `ralphy.db`. Use it directly with `--root`, and retain the returned immutable Workspace ID. For Project commands, use the immutable Project `id` returned by `new`:

```bash
ralphy --root <data_root> --workspace <workspace_id> new "A coffee shop poster"
ralphy --root <data_root> --project <project_id> provider list
```

Place scope flags before the verb. Generation accepts exactly one destination; do not combine its Project and Workspace destinations. Workspace credentials are not inherited by Projects.

## Public configuration

Non-secret Workspace settings are stored in SQLite and managed through `ralphy config` in an explicit Workspace scope. Settings must not contain credential keys or secret values. The legacy global link at `~/.config/ralphy/config.json` can still point source developers at a checkout; it is not the provider credential store.

| Override | Purpose |
|---|---|
| `--root <path>` | Exact local data directory containing `ralphy.db`. |
| `--workspace <id>` | Explicit Workspace context. |
| `--project <id>` | Explicit Project context. |
| `--session <id>` | Immutable agent Session context. |
| `--cwd <path>` | Working-directory discovery for an existing library. |
| `RALPHY_PROJECT_DIR` | Compatibility checkout link for source development. |
| `RALPHY_DOCTOR_NO_UPDATE_CHECK=1` | Disable doctor's release lookup. |
| `NO_COLOR` | Disable ANSI output. |
