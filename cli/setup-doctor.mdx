For CLI **0.4.0**, `setup` initializes local storage and `doctor` reports runtime prerequisites. Configure provider credentials separately in the scope that will use them.

## Setup

```bash
ralphy setup --non-interactive
ralphy --root /absolute/path/to/library setup --non-interactive
ralphy setup --status
```

Setup creates a SQLite store and one default Workspace when none exists, with no source checkout required. Its JSON summary includes `data_root`, `workspace_id`, `project_dir`, capabilities, and errors. `project_dir` can be null for standalone installation. With multiple Workspaces, `workspace_id` is null: list them and choose one explicitly. `--status` reports capability status without creating a store.

Setup discovers an existing library above the working directory. Legacy filesystem data must be migrated before it can become a SQLite library; setup preserves it and refuses initialization there.

Compatibility options `--link`, `--unlink`, and `--project-dir` remain for source developers. Credential flags such as `--openrouter-key`, `--elevenlabs-key`, and `--keys-from-env` are deprecated and refused. Setup does not verify provider keys or write `.env`.

Full flags: [setup reference](/reference/cli/setup).

## Credentials

Use inherited shell credentials or configure a scoped encrypted credential privately through stdin:

```bash
ralphy --root <data_root> --workspace <workspace_id> provider auth set openrouter --stdin
ralphy --root <data_root> --workspace <workspace_id> provider auth status openrouter
```

Use your own terminal and a hidden prompt or existing shell variable; never put a literal key in a command or chat. Encrypted persistence uses macOS Keychain. On other platforms, export credentials before starting the CLI.

A Project has a separate credential scope. After `new`, use the immutable returned `id`:

```bash
ralphy --root <data_root> --project <project_id> provider auth set openrouter --stdin
ralphy --root <data_root> --project <project_id> provider auth status openrouter
```

Workspace credentials do not automatically become Project credentials. Put global scope flags before the verb. For generation, pass a Project destination or a Workspace destination, never both.

## Doctor

```bash
ralphy --root <data_root> --workspace <workspace_id> doctor
ralphy --root <data_root> --project <project_id> doctor
```

Doctor reports the CLI version, installation mode, dependencies, configured providers, blockers, warnings, and update information. It does not generate media. A configured key is not proof of provider acceptance. Use the explicit Project scope when diagnosing a Project's missing key.

For a JSON health gate:

```bash
ralphy --root <data_root> --project <project_id> doctor --json | jq -e '.blockers | length == 0'
```

Doctor checks for newer releases with a bounded timeout. Set `RALPHY_DOCTOR_NO_UPDATE_CHECK=1` to disable that lookup.

## Common failures

| Symptom | Remediation |
|---|---|
| Missing external dependency | Install the tool named by doctor, then repeat the scoped check. |
| Provider not configured | Export the key before launching the CLI or use scoped `provider auth set --stdin`. |
| Project key missing after Workspace setup | Configure that Project's credential scope or inherit a shell credential. |
| `E_MIGRATION_INCOMPLETE` or `E_LEGACY_LAYOUT` | Preserve the existing library and follow the migration procedure. |
| More than one Workspace | List Workspaces and pass the chosen immutable ID explicitly. |
