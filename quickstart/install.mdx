These instructions target CLI **0.4.0** and the matching Ralphy plugin. Install the CLI, add the plugin to your agent, and choose a local directory for your content. A source checkout is only needed to develop Ralphy.

## Install the CLI

<Tabs>
  <Tab title="macOS (Homebrew)">
    ```bash
    brew install alecs5am/tap/ralphy
    ```

    Upgrade with `brew upgrade ralphy`.
  </Tab>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/alecs5am/ralphy/main/install.sh | sh
    ```

    The installer downloads the standalone binary to `~/.local/bin/ralphy` and configures your PATH when needed. Open a new terminal afterward.
  </Tab>
  <Tab title="npm (cross-platform)">
    ```bash
    npm install -g @alecs5am/ralphy
    ```

    The wrapper downloads the same platform binary. Upgrade with `npm update -g @alecs5am/ralphy`.
  </Tab>
</Tabs>

Check `ralphy --version` before continuing. The standalone binary includes its Bun runtime. `ralphy doctor` identifies external rendering tools such as FFmpeg that your workflow still needs.

## Add the agent plugin

Follow the [Ralphy plugin installation instructions](https://github.com/alecs5am/ralphy-plugin#install) for Claude Code or Codex. The plugin carries the routing skill, production playbooks, and reference documents; you do not need to clone the runtime repository to obtain them.

## Initialize a library

In the directory where you want to keep content, run:

```bash
ralphy setup --non-interactive
```

For a fixed location independent of the working directory:

```bash
ralphy --root /absolute/path/to/library setup --non-interactive
```

Setup creates a SQLite store and a default Workspace when none exists. Retain `data_root` and `workspace_id` from the JSON response. Re-running setup preserves existing Workspaces. If the result has a null `workspace_id`, list the Workspaces and choose one explicitly:

```bash
ralphy --root <data_root> workspace list
```

Existing legacy data requires migration; setup does not replace it with an empty library.

## Configure keys privately

OpenRouter serves image, video, and LLM requests; ElevenLabs serves voice and music. Obtain keys from [OpenRouter](https://openrouter.ai/keys) and [ElevenLabs](https://elevenlabs.io/app/settings/api-keys). Configure only the providers your workflow needs.

Export credentials in your own shell before launching the agent or CLI, or pipe them privately into the scoped encrypted store:

```bash
ralphy --root <data_root> --workspace <workspace_id> provider auth set openrouter --stdin
```

Supply stdin from a hidden terminal prompt or an existing shell variable. Never paste keys into chat, place literal keys in argv or shell history, or save them in a project's `.env`. Encrypted persistence uses macOS Keychain; on other platforms, use credentials exported in the parent shell.

`setup` initializes storage. It does not accept keys, ping providers, or write `.env`. Legacy flags such as `--openrouter-key` and `--keys-from-env` are refused.

## Create content in an explicit scope

```bash
ralphy --root <data_root> --workspace <workspace_id> new "A coffee shop poster"
```

Retain the immutable `id` (`prj_...`) from the response. Use it for Project commands, with scope flags before the verb:

```bash
ralphy --root <data_root> --project <project_id> provider auth status openrouter
ralphy --root <data_root> --project <project_id> doctor
```

Workspace credentials are not inherited by Projects. If the Project has no credential, configure the same Project scope privately with `provider auth set <provider> --stdin`, or use inherited shell credentials. For generation, pass the Project destination alone; do not also pass `--workspace`.

Configuration status confirms key presence, not provider acceptance. Installation does not require a paid generation. Continue to [Your first video](/quickstart/first-video) after selecting your scope and provider.
